# The Result Pattern & Prisma Type Extraction

## 1. The Result Pattern (Railway-Oriented Programming)

### Why Throwing Exceptions for Domain Errors is an Anti-Pattern
Throwing `new Error()` for normal business failures (e.g. `CouponExpired`, `InsufficientBalance`, `UserNotFound`) has severe costs:
1. It is slow (V8 captures the full stack trace on every throw).
2. It breaks the type system: callers cannot see what errors a function might throw from its return type signature.
3. It forces callers into untyped `try/catch` blocks.

### The Typed Result Contract
```typescript
export type Result<T, E = Error> =
  | { readonly ok: true; readonly data: T }
  | { readonly ok: false; readonly error: E };

export const ok = <T>(data: T): Result<T, never> => ({ ok: true, data });
export const fail = <E>(error: E): Result<never, E> => ({ ok: false, error });
```

### Domain Error Unions
```typescript
export type TransferFundsError =
  | { code: 'INSUFFICIENT_FUNDS'; balanceCents: number; requestedCents: number }
  | { code: 'ACCOUNT_FROZEN'; freezeReason: string }
  | { code: 'DAILY_LIMIT_EXCEEDED'; remainingLimitCents: number };

export async function transferFunds(
  fromId: number, 
  toId: number, 
  amountCents: number
): Promise<Result<{ transactionId: string }, TransferFundsError>> {
  // Logic returning ok(...) or fail(...)
}
```

The caller is **forced by the compiler** to check `if (!result.ok)` before accessing `result.data`.

## 2. Precise Prisma Type Extraction (Zero `as any`)

### The Lie of Raw Model Returns
If you query a user with `select: { id: true, email: true }`, returning `Promise<User>` is a lie. Downstream code that accesses `user.passwordHash` will crash with `undefined` at runtime.

### The `satisfies` & `Prisma.GetPayload` Standard
Use `satisfies Prisma.<Model>Select` and `Prisma.<Model>GetPayload` to extract the exact TypeScript type generated by Prisma:

```typescript
import { Prisma } from '@prisma/client';

// 1. Declare the exact select contract
export const userWithOrgSelect = {
  id: true,
  email: true,
  firstName: true,
  lastName: true,
  organization: {
    select: {
      id: true,
      codeName: true,
      timezone: true,
    }
  }
} as const satisfies Prisma.OrganizationUserSelect;

// 2. Infer the exact TypeScript return shape
export type UserWithOrgDTO = Prisma.OrganizationUserGetPayload<{
  select: typeof userWithOrgSelect;
}>;

// 3. The function returns the exact type queried from the DB
export async function getUserWithOrg(userId: number): Promise<UserWithOrgDTO | null> {
  const prisma = getPrisma();
  return prisma.organizationUser.findUnique({
    where: { id: userId },
    select: userWithOrgSelect,
  });
}
```
Zero `as any`, zero type assertions, 100% truthful to the database query.
